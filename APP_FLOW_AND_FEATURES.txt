1. SYSTEM OVERVIEW
================================================================================

This is a comprehensive attendance tracking and management system for educational
institutions. The system supports role-based access control with three main user
types: Admin (HOD), Faculty (Teachers), and Students.

KEY CHARACTERISTICS:
- Multi-HOD Support: Each HOD (Head of Department) manages separate courses
- Shared Infrastructure: Classrooms and labs are shared across all departments
- Global Time Conflict Checking: Prevents double-booking of resources
- Complete Audit Logging: All admin actions are logged and visible to all admins
- Role-Based Leave Approval Chain: Student → Faculty → Admin approval hierarchy
- OTP-Based Attendance: Secure attendance marking using One-Time Passwords
- Real-Time Notifications: Updates on leave status and session changes

ADMIN PANEL FEATURES:

Feature 1: OTP SETTINGS
------------------------
Purpose: Configure One-Time Password validity duration
Flow:
  1. Click "OTP Settings" card
  2. Navigate to OTPSettingsScreen
  3. View current OTP validity time (default: 10-300 seconds)
  4. Adjust validity slider or enter custom value
  5. Validation: Value must be between 5-300 seconds
  6. Save changes
  7. Changes apply immediately to new OTP generations
  8. Audit log entry: "OTP Validity Updated from X to Y seconds"

Usage Example:
- Before class: Set OTP validity to 10 seconds
- For makeup sessions: Increase to 20 seconds if needed

Feature 2: INFRASTRUCTURE MANAGEMENT
-------------------------------------
Purpose: Create and manage classrooms, labs, and other physical resources
Flow:
  1. Click "Infrastructure" card
  2. Navigate to InfrastructureScreen
  3. View list of all available infrastructure (Classroom A, Lab 1, etc.)

Sub-feature 2a: CREATE NEW INFRASTRUCTURE
  1. Click "Add Infrastructure" button
  2. Enter details:
     - Name (e.g., "Classroom A101")
     - Type (Classroom/Lab/Seminar Hall/Auditorium)

     - Location (Building and Floor info)
  3. Click "Create"

  5. Audit log: "Infrastructure created: Classroom A101"

Sub-feature 2b: BOOK INFRASTRUCTURE FOR SESSION
  1. When creating/editing a session
  2. Select infrastructure from dropdown
  3. System checks: Is infrastructure available at this time?
  4. Global Time Conflict Check:
     - Compares against ALL existing bookings across ALL departments
     - If conflict found: "Infrastructure booked at this time"

  5. If available: Session scheduled successfully
  6. Audit log: "Infrastructure booked for Session ID 123"

Sub-feature 2c: VIEW INFRASTRUCTURE SCHEDULE

  2. See weekly/monthly booking calendar

Feature 3: OTP GENERATION
-------------------------
Purpose: Secure attendance marking using One-Time Passwords

OTP System Details:
- Random 4-6 digit code (configurable by admin)
- Valid for 10 seconds (configurable by admin)
- One-time use only
- Associated with specific session

START OTP:
  Purpose: Mark student arrival at class
  When: Faculty generates 2-3 minutes after class starts
  Process:
    1. Faculty clicks "Generate START OTP" on session card
    2. System generates code: "4829"
    3. Code displayed on faculty's screen
    4. Faculty announces: "Your START OTP is 4829"
    5. Faculty monitors: Student app shows "Enter OTP"
    6. Countdown: 10 seconds remaining
    7. Students enter code
    8. If correct: Same device can enter END OTP
    9. If wrong: "Invalid code, please try again"
    10. After 10 seconds: Code expires, "OTP Expired" message
    11. Faculty can regenerate

END OTP:
  Purpose: Mark class end and finalize attendance
  When: Faculty generates 2-3 minutes before class ends
  Process:
    1. Faculty clicks "Generate END OTP" on session card
    2. New code displayed: "7341"
    3. Faculty announces: "Your END OTP is 7341"
    4. Students who entered START OTP now see: "Enter END OTP"
    5. Process same as START OTP
    6. Student attendance marked as "PRESENT" after both OTPs
    7. Session marked complete
    8. Attendance locked (cannot be edited)

OTP Security:
- Generated using cryptographic randomness
- Expires after configured time
- Cannot be reused
- Tied to specific session and infrastructure
- Logs all OTP entry attempts

Example Timeline:
  10:00 AM - Class begins
  10:03 AM - Faculty generates START OTP: "6234"
  10:03-10:13 - Students entering OTP
  10:10 AM - Faculty generates reminder (OTP still valid)
  10:13 AM - OTP expires
  10:50 AM - Faculty generates END OTP: "8921"
  10:50-11:00 - Students entering END OTP
  11:00 AM - Class ends, attendance locked

Feature 1: ATTENDANCE MARKING
-----------------------------
Purpose: Mark attendance using OTP provided by faculty

Process - Marking Present:
  1. Student logs into app
  2. Navigates to "Today's Sessions" or "Mark Attendance"
  3. Sees list of all sessions today:
     - Course name
     - Time
     - Room
     - Faculty name
  4. 10 minutes before class: "Mark Attendance" button becomes active
  5. Faculty announces START OTP in class: "4829"
  6. Student clicks "Mark Attendance"
  7. Screen shows "Enter START OTP"
  8. Student enters: 4829
  9. System validates (has 10 seconds before OTP expires)
  10. If correct: "Received START OTP ✓"
  11. Student now sees: "Class ongoing - Enter END OTP when provided"
  12. Faculty announces END OTP: "7341"
  13. Student sees: "Enter END OTP"
  14. Student enters: 7341
  15. System validates
  16. If correct: "✓ Attendance Marked - PRESENT"
  17. Session locked for student
  18. Student cannot re-mark attendance

What if Student Misses OTP:
  - If START OTP expires: "OTP Expired - Please contact faculty"
  - If END OTP expires: Still marked present (if START was marked)
  - Student can request faculty to issue new OTP
  - Faculty can regenerate OTP if student was in class

Marking Absent (No Action):
  - If student doesn't enter any OTP by class end
  - Status automatically: "ABSENT"
  - No manual entry needed
  - Automatically reflects in attendance records

4.1 ATTENDANCE MARKING WORKFLOW (Complete Day Timeline)
================================================================================

SCENARIO: Advanced Data Structures Class (CS-201)
Time: 10:00 AM - 10:55 AM
Room: Computer Lab A103
Faculty: Dr. Rajesh Kumar
Students: 45 enrolled

BEFORE CLASS (09:50 - 10:00 AM):
  Faculty Actions:
    1. Reaches lab at 09:50
    2. Opens app → Dashboard
    3. Checks "Today's Sessions"
    4. Sees CS-201, 10:00 AM, Lab A103
    5. Clicks "Session Details"
    6. Verifies student roster (45 expected)
    7. Confirms room is ready
    8. Status shows: "Ready to Start"
  
  Student Actions:
    1. Arrive at lab 09:55
    2. Settle down, take seats
    3. Open app
    4. Navigate to "Today's Sessions"
    5. See CS-201 listed
    6. Button shows: "Attendance Opens at 10:00"

AT CLASS START (10:00 AM):
  Faculty Actions:
    1. Roll call begins
    2. Takes attendance traditional route (visual confirmation)
    3. Waits 2-3 minutes (till 10:03)
    4. All students settled, ready to mark
  
  Student Actions:
    1. Open app
    2. "Mark Attendance" button now active
    3. Screen ready to accept OTP

MARKING START ATTENDANCE (10:03 AM):
  Faculty Action:
    1. Clicks "Generate START OTP"
    2. System generates: "4829" (4-digit code)
    3. OTP valid for 10 seconds (countdown shown)
    4. Large display on faculty's screen
    5. Faculty announces: "Your START OTP is 4829"
    6. Faculty notes time in system: "OTP shown at 10:03"
  
  Student Actions:
    1. Hear faculty announce code: "4829"
    2. Click "Mark Attendance" button
    3. Text field appears: "Enter START OTP"
    4. Type code: 4829
    5. Hit "Submit"
    6. System validates in real-time
    7. If correct: Screen shows "✓ START OTP Received"
    8. If wrong: "✗ Invalid code, try again"
    9. If too late: "✗ OTP Expired (10 seconds passed)"
  
  System Processing:
    1. Accepts OTP entry within 10 seconds
    2. Records exact time: 10:03:45 (for audit)
    3. Links student to session

5. TECHNICAL IMPLEMENTATION
================================================================================

Authentication & Security:
- JWT Token-Based Authentication
- Bcrypt Password Hashing
- Token stored in AsyncStorage

OTP System:
- 4-digit One-Time Passwords
- Generated via cryptographic randomness
- Valid for admin-configured time (default 10 seconds)
- Stored in Redis cache with auto-expiry
- One-time use only per session

Data Storage:
- All data stored in MySQL database
- AsyncStorage for local token storage
- Redis cache for OTP (10-second expiry)
- Historical data: Permanently retained for audit

6.1 Multi-HOD Data Isolation Model
================================================================================

Three Tiers of Data Access:

Tier 1: DEPARTMENT-ISOLATED DATA
  - Courses created by this HOD ONLY
  - Sessions created in these courses ONLY
  - Faculty assigned by this HOD ONLY
  - Each HOD sees separate data

Tier 2: SHARED DATA (Department-Agnostic)
  - Infrastructure (classrooms, labs)
  - Global time conflict checking
  - Can be booked by any HOD's courses
  - Prevents double-booking across departments

Tier 3: COMPLETE VISIBILITY (Audit Only)
  - All admin actions logged
  - All HODs can view complete audit trail
  - No data hidden from other HODs in logs
  - Transparency and accountability

Real-World Example:
  "Faculty of Engineering (HOD: Dr. A) + Faculty of Science (HOD: Dr. B)"
  
  Course Isolation:
  - Dr. A sees only Engg courses (DSA, OOP, etc.)
  - Dr. B sees only Science courses (Physics, Chemistry, etc.)
  - Dr. B cannot edit Dr. A's courses
  - When creating session: Lists only their own courses
  
  Infrastructure Sharing:
  - Classroom A101 is shared resource
  - Dr. A books it for "DSA" on Monday 10-11 AM
  - Dr. B tries to book same: "Conflict - Already booked at this time"
  - Dr. B can book it for 11-12 PM instead
  
  Audit Transparency:
  - Dr. A sees in audit log: "Dr. B created course XYZ, Dr. B approved leave for student M"
  - Dr. B sees in audit log: "Dr. A updated infrastructure, Dr. A approved course"
  - Both see: Complete system history (transparency)
  - Can verify no unauthorized actions by peer HOD
